## 1. 产品概述

### 1.1 产品定位

**天融（SkyFusion）是一款完全离线的 Windows 桌面格式转换工具**，当前以**音频转换**与**图片转换、压缩**为核心能力。所有转换工作通过本机 `ffmpeg.exe` / `ffprobe.exe` 进程完成，全程不联网、不注入、无后台服务、不写注册表。

| 项目 | 值 |
| --- | --- |
| 中文名 / 英文名 | 天融 / SkyFusion |
| 中文 Slogan | 天融万物，格式无界 |
| 英文 Slogan | Fuse Anything, Convert Anything |
| 主程序 | `SkyFusion.exe` |
| 主窗口标题 | `天融 - SkyFusion` |
| 程序集名 / 根命名空间 | `SkyFusion` / `AudioConverter`（命名空间保留历史名） |
| 当前版本 | 1.2.1 |
| 许可 | 源码 MIT；发布包内含 FFmpeg（GPLv3） |

### 1.2 目标用户与使用场景

- 需要在**内网 / 离线环境**（生产网、涉密网、无外网终端）中转换音视频与图片的用户；
- 需要**免安装、可拷贝到 U 盘直接运行**的便携工具的用户；
- 仍在运行 **Windows 7 SP1** 而无法使用 Electron / Flutter / 新版 .NET 工具的存量终端。

### 1.3 四条硬性设计约束

这四条约束是产品的核心卖点，任何一条不满足即视为不合格实现：

1. **必须能在 Windows 7 SP1 x64 上运行**；
2. **完全离线**：不下载、不联网校验、不调用云端 API；
3. **不引入第三方运行时依赖**：不用 NuGet UI 库、不用 WebView、不起本地 HTTP 服务、不用 Node / Electron / Flutter；
4. **交付前必须验证**：编译通过（0 警告 0 错误）、程序能启动、能真实完成一次转换。

### 1.4 系统要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 7 SP1 x64 / Windows 10 x64 / Windows 11 x64 |
| 架构 | 仅 64 位（主程序 `x64`，32 位系统不支持） |
| 运行时 | .NET Framework 4.8（Win10 1903+ 与 Win11 自带） |
| Win7 额外补丁 | KB4490628（服务堆栈，必须先装）、KB4474419（SHA-2 签名支持）、KB4019990（WPF 依赖 `d3dcompiler_47.dll`） |

## 2. 技术栈

### 2.1 技术选型总表

| 层次 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | C# 8.0 | `LangVersion=8.0`，使用可空引用以外的 C# 8 语法 |
| UI 框架 | WPF (`UseWPF=true`) | 系统自带，Win7 可用，无第三方 UI 库 |
| 架构模式 | MVVM | View(XAML) / ViewModel / Service / Core 单向依赖 |
| 目标框架 | .NET Framework 4.8 (`net48`) | Win7 SP1 可安装的最高主流版本 |
| 目标平台 | x64 (`PlatformTarget=x64`) | 避免 32 位进程内存与 FFmpeg 位数不一致 |
| 输出类型 | `WinExe` | 无控制台窗口 |
| 多媒体内核 | FFmpeg 7.0 essentials（gyan.dev 静态构建） | 独立进程调用，不做链接 |
| JSON 持久化 | `DataContractJsonSerializer` | .NET 自带，零第三方依赖 |
| 依赖注入 | 手写组合根 `Services/AppServices.cs` | 不引入 DI 容器 |
| 安装打包 | Inno Setup (`scripts/SkyFusion.iss`) | 生成 `SkyFusion-Setup-<版本>.exe` |
| 构建 | `dotnet build`（无需 Visual Studio） | 通过 `Microsoft.NETFramework.ReferenceAssemblies` 提供 net48 参考程序集 |

### 2.2 关键选型理由

- **为什么是 WPF 而不是 WinForms**：需要圆角卡片、自定义标题栏、矢量图标、DataTemplate 驱动的页面切换与数据绑定，WinForms 无法低成本实现；同时 WPF 属 .NET Framework 自带组件，满足"零第三方依赖"。
- **为什么不用 Electron / Flutter / WebView**：三者在 Windows 7 上均无法稳定运行或会引入巨大运行时体积，与核心卖点直接冲突。
- **为什么 FFmpeg 以独立进程调用**：避免 GPL 传染到本项目源码，避免 DLL 版本地狱，避免 UCRT / VC 运行库分发问题；同时天然获得崩溃隔离能力（FFmpeg 崩溃不会带走主程序）。
- **为什么 JSON 不用 Newtonsoft.Json**：`DataContractJsonSerializer` 已能满足 `settings.json` / `history.json` 的读写需求，少一个依赖就少一份兼容性风险。

### 2.3 编译期依赖（仅一个）

```xml
<PackageReference Include="Microsoft.NETFramework.ReferenceAssemblies" Version="1.0.3" PrivateAssets="all" />
```

该包**只用于在没有 Visual Studio 的机器上编译 net48**，`PrivateAssets=all` 保证它不会流入任何发布产物。引用程序集仅 `System.Windows.Forms`（仅用于 `Application.EnableVisualStyles()`）与 `System.Configuration`。

### 2.4 第三方组件

| 组件 | 版本 | 许可 | 集成方式 |
| --- | --- | --- | --- |
| FFmpeg / FFprobe | 7.0-essentials_build（gyan.dev，gcc 13.2.0，static） | GPLv3 | 独立进程调用，随包分发 |
| .NET Framework | 4.8 | 微软许可 | 目标框架；Win7 便携包附带离线安装包 |
| WPF / 系统字体 | 随系统 | 微软许可 | 不复制字体文件 |

UI 风格参考过 Codex Desktop、FlClash、PCL2 的布局与交互气质，**未复制其源码、素材或品牌资源**，图标与界面元素均为本项目原创。

## 3. 系统架构

### 3.1 分层模型

```text
┌──────────────────────────────────────────────────────────────┐
│  View 层（Modules/*/xxxView.xaml、Shell/MainWindow.xaml）      │
│  纯 XAML 声明 + 少量视图相关代码（拖拽、窗口、弹窗宿主）          │
└───────────────────────────┬──────────────────────────────────┘
                            │ 数据绑定 / Command
┌───────────────────────────▼──────────────────────────────────┐
│  ViewModel 层（Modules/*/xxxViewModel.cs、Shell/ShellViewModel）│
│  页面状态、命令、列表、计数、脏值判断、事件订阅                    │
└───────────────────────────┬──────────────────────────────────┘
                            │ 方法调用
┌───────────────────────────▼──────────────────────────────────┐
│  Service 层（Services/：AppServices 组合根、Settings、History、  │
│  Toast、Log、LogExporter）                                      │
└───────────────────────────┬──────────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────────┐
│  Core 层（Core/：FfmpegLocator、FfprobeRunner、FfmpegRunner、    │
│  ImageFfmpegRunner、ConversionTaskManager、OutputLocation、     │
│  OutputPathResolver、CommandLine、MediaInfo）                   │
│  纯转换逻辑，无任何 UI 依赖                                      │
└───────────────────────────┬──────────────────────────────────┘
                            │ ProcessStartInfo（独立进程）
┌───────────────────────────▼──────────────────────────────────┐
│  ffmpeg.exe / ffprobe.exe（本机可执行文件，同机调用）             │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 架构铁律（违反即返工）

- **UI 不直接调用 FFmpeg**，也不允许拼接 FFmpeg 参数；参数只允许出现在 `Core/FfmpegRunner.cs`、`Core/ImageFfmpegRunner.cs`、`Core/FfprobeRunner.cs`。
- **模块之间不互相引用页面控件**；共享控件放 `Components/`，共享样式放 `Theme/`。
- 转换进度与状态只通过 `ConversionTaskManager` 的事件 → ViewModel → UI 单向流动。
- FFmpeg 只以独立进程方式调用（`ProcessStartInfo` + 重定向输出 + `CreateNoWindow`），不做 DLL 链接、不做注入。
- 分层调用只能自上而下，不能反向（Core 不得引用 Services / Modules）。

### 3.3 模块职责矩阵

| 位置 | 职责 |
| --- | --- |
| `App.xaml(.cs)` | 启动装配、单实例检测、全局异常兜底、命令行文件入参 |
| `Shell/` | 自定义标题栏、侧栏导航、页面缓存、弹窗遮罩宿主 |
| `Modules/Conversion` | 音频转换：上传、列表、参数、状态显示 |
| `Modules/ImageCompression` | 图片转换、压缩：预览、画质、缩放 |
| `Modules/History` | 历史展示、搜索、筛选、排序、清空 |
| `Modules/Settings` | 三组共八项设置 |
| `Modules/About` | 版本、FFmpeg 版本、兼容性信息、日志导出 |
| `Modules/Office` | 占位入口（尚未实现） |
| `Components/` | 跨页面复用控件（`EmptyState`、`TriStateCheckBox`） |
| `Theme/` | 色板、字体、间距、控件模板、值转换器 |
| `Core/` | 纯转换逻辑，无 UI 依赖 |
| `Services/` | 组合根、设置、历史、弹窗、日志 |
| `Data/` | JSON 轻量持久化 |
| `Models/` | 领域模型与枚举 |

### 3.4 关键调用链

**音频转换**

```text
ConversionView（勾选 + 点「开始转换」）
  → ConversionViewModel.StartConversionAsync()
    → 组装 List<ConversionTask>（含逐个文件解析出的输出目录）
      → AppServices.TaskManager.RunAsync(tasks, progress, token)
        → 逐个任务：OutputPathResolver.Resolve() 决定目标路径
        → FfprobeRunner.ProbeAsync() 取得时长 / 音视频流信息
        → FfmpegRunner.ConvertAsync() 启动 ffmpeg，解析 -progress 输出
        ← IProgress<ConversionTaskUpdate> 回传（Progress<T> 自动回到 UI 线程）
  ← 结果落 HistoryService
  ← ToastService 弹完成提示（带「打开输出位置」）
```

**图片压缩**

```text
ImageCompressionView（选格式 / 拖画质 / 选缩放）
  → ImageCompressionViewModel.SchedulePreview()（500ms 防抖）
    → ImageFfmpegRunner.ConvertAsync() 生成到 %TEMP%\AudioConverter\ImagePreview
      → ImageItemViewModel.SetPreview() 刷新预览图与体积对比
  → 点「开始压缩」→ 逐张调用 ImageFfmpegRunner → 写历史 → 弹提示
```

## 5. 功能模块设计

### 5.1 应用外壳 Shell

#### 启动流程（`App.xaml.cs`）

```text
OnStartup
 ├─ AcquireSingleInstance()     命名互斥体 Local\SkyFusion.SingleInstance.Shell
 │   ├─ 已有实例 → Toast 提示「检测到已打开同类型软件」
 │   │            → AllowSetForegroundWindow + FindWindow/ShowWindow/SetForegroundWindow
 │   │            → PostMessage 广播 SkyFusion.ActivateRunningWindow
 │   │            → Shutdown()
 │   └─ 获取成功 → 继续
 ├─ 注册 DispatcherUnhandledException（记录日志 + MessageBox + Handled=true）
 ├─ Application.EnableVisualStyles()
 ├─ new AppServices()（组合根：设置、历史、FFmpeg 定位、任务管理器、探测/图片 Runner）
 ├─ new MainWindow { DataContext = new ShellViewModel(services) }
 ├─ window.Show(); HookActivateMessage(window)
 └─ 命令行参数非空 → ShellViewModel.OpenMediaFiles(args)
```

单实例实现要点：

- 使用 `Local\` 前缀的命名互斥体，限制在**同一登录会话**内；
- 互斥体随进程结束自动销毁，`createdNew=false` 即代表已有实例；
- 受限环境创建失败时**不阻塞启动**（返回 `true`），保证程序仍可用；
- 唤醒采用"三保险"：先交出前台权限（`AllowSetForegroundWindow`），再直接 `FindWindow` 恢复并置前，最后广播自定义窗口消息由对方自己 `Activate()`（对方也能处理最小化状态）。

#### 自定义标题栏

主窗口使用 `WindowStyle="None"` + `WindowChrome`（`CaptionHeight=38`、`ResizeBorderThickness=6`、`CornerRadius=12`、`UseAeroCaptionButtons=False`），标题栏由三段构成：

| 区域 | 内容 |
| --- | --- |
| 左侧 | Logo（`/Assets/app-logo.png`，22×22）+「文件」菜单 +「帮助」菜单 |
| 中部 | 空白拖动区（`MouseLeftButtonDown` → `DragMove()`，双击 → 最大化/还原） |
| 右侧 | 最小化 / 最大化 / 关闭（40×36 矢量图标按钮，`IsHitTestVisibleInChrome=True`） |

「文件」菜单含二级菜单「导入」（音频 / 视频、图片、Word / Excel 等〔禁用占位〕）与「关闭软件」；「帮助」菜单含文档、当前版本、关于、导出日志。二级菜单采用 **320ms 延迟关闭定时器**（`DispatcherTimer`），避免鼠标斜向移动时菜单意外收起。

#### 侧栏导航

| 属性 | 值 |
| --- | --- |
| 展开宽度 | 226px |
| 折叠宽度 | 70px |
| 折叠阈值 | 窗口 `ActualWidth >= 1000` 时展开 |
| 分组 | 上组：音频转换 / 图片转换、压缩 / 办公转换 / 历史；下组：设置 / 关于 |
| 导航样式 | `NavListBox` + `NavItem`；选中态 `Brush.AccentSoft` 底 + `Brush.Accent` 文字 |

**页面缓存**：`ShellViewModel` 用 `Dictionary<AppPage, ViewModelBase> _pages` 缓存页面实例，切换导航不重建 ViewModel；每次切换调用 `page.OnActivated()`，供页面同步其它页改动过的设置（典型场景：在转换页改了输出目录后回到设置页）。

`AppPage` 枚举决定页面：`Conversion / ImageCompression / Office / History / Settings / About`，对应关系在 `Shell/ShellDataTemplates.xaml` 中以 `DataTemplate` 声明，新增页面必须同步四处：枚举、导航项、DataTemplate、`Modules/<名称>/` 的 View + ViewModel。

**外部文件入参**：`ShellViewModel.OpenMediaFiles(paths)` 判断是否全部为图片扩展名（`.jpg/.jpeg/.png/.webp/.bmp`）——是则切到图片页并 `AddPaths`，否则切到音频页。支持命令行参数与资源管理器"打开方式"。

#### 弹窗遮罩宿主

`MainWindow` 实现 `Services/IModalMaskHost`：

- `ShowModalMask()`：给 `ShellRoot` 挂 `BlurEffect{Radius=8, Gaussian}`，并把 `ModalMask`（`Brush.ModalMask` = `#4D000000`）淡入（120ms）；
- `HideModalMask()`：立即移除模糊效果（模糊很吃渲染，必须摘掉）并把遮罩置为 `Collapsed`。

### 5.2 音频转换（`Modules/Conversion`）

**输入与识别**

| 项目 | 值 |
| --- | --- |
| 允许扩展名 | `.mp3` `.wav` `.flac` `.mp4` `.mkv` |
| 类型判定 | `.mp4`/`.mkv` → `FileKind.Video`（列表显示"音轨"标签），其余 → `FileKind.Audio` |
| 去重 | 按 `FilePath` 不区分大小写去重 |
| 添加方式 | 拖拽到上传区 / 点击上传区 / 文件菜单导入 / 命令行入参 |
| 异步探测 | 添加后调用 `FfprobeRunner` 读取时长，失败保持 `—` |

**列表与选择**

- 每行：文件名、完整路径（`MetaText`）、格式 Chip、类型标签、状态、大小、时长、行内进度条、移除按钮；
- 三态全选：`TriStateCheckBox`，`IsThreeState=true` 且重写 `OnToggle()`，点击只在全选 / 全不选之间切换，不进入 indeterminate；
- 计数联动：`SummaryText` = 「已添加 N 个文件，已选择 M 个文件」，开始按钮文案 = 「开始转换(M)」。

**转换控制**

- 输出格式下拉：`OutputFormatOption`（MP3 · 320 kbps · CBR / WAV · 16-bit PCM / FLAC · Compression Level 5），默认取设置中的 `DefaultOutputFormat`；
- 输出目录：只读展示 `OutputDirectoryDisplay`，点「浏览…」使用 `FolderBrowserDialog` 选择后**立即切换为自定义模式并存盘**，可一键「改回程序所在文件夹」；
- 运行中状态条：当前任务名、进度百分比、速度、取消按钮。

**状态机（`ConversionStatus`）**

```text
Waiting ──开始──▶ Running ──成功──▶ Completed
                     │
                     ├─失败（含重试耗尽）──▶ Failed（记录 ErrorMessage）
                     ├─用户取消──────────▶ Cancelled
                     └─输出已存在跳过─────▶ Skipped
```

状态 → 视觉映射由 `StatusToBrushConverter` / `StatusToForegroundConverter` 统一处理：运行=蓝（`AccentSoft`/`Accent`）、完成=绿（`SuccessSoft`/`Success`）、失败=红（`DangerSoft`/`Danger`）、取消/跳过=橙（`WarningSoft`/`Warning`）、等待=灰（`SurfaceAlt`/`TextSecondary`）。

**完成提示**

转换结束后按结果弹出不同形态的提示：

- 全部取消/跳过 → `Warning`：「转换已取消/跳过：成功 x，失败 y，取消/跳过 z」；
- 有失败 → `Error`；
- 有成功 → `Success`，并且**单文件**给「打开文件所在位置」（`explorer.exe /select,`），**多文件**给「打开输出目录」。

**历史写入**：每次转换按结果生成 `HistoryEntry`（文件名、原格式、目标格式、输出路径、大小、耗时、时间戳、错误码、错误信息），通过 `History.AddRange` 一次性写入。

### 5.3 图片转换、压缩（`Modules/ImageCompression`）

| 项目 | 值 |
| --- | --- |
| 输入格式 | `.jpg` `.jpeg` `.png` `.webp` `.bmp` |
| 输出格式 | WebP（默认，有损，支持透明）/ JPG（兼容性最好，不支持透明）/ PNG（无损，尺寸缩小有限） |
| 画质 | 1–100，默认 75，滑块与数值输入双向联动；PNG 时禁用 |
| 缩放 | 原尺寸 / 等比 80% / 60% / 50% / 最长边 ≤2560 / ≤1920 / ≤1280 |
| 预览 | 左右对比（原图 vs 压缩后预览）+ 体积与节省百分比 |

**实时预览管线**

```text
参数变化（格式 / 画质 / 缩放 / 新增文件）
  → SchedulePreview()：取消上一轮 CTS，新建 CTS
    → GeneratePreviewsAsync()：await Task.Delay(500, token)  ← 500ms 防抖
      → 逐张 ImageFfmpegRunner.ConvertAsync() 输出到
         %TEMP%\AudioConverter\ImagePreview\<GUID><ext>
        → SetPreview(path, size) → 刷新预览图 + CompareResultText
```

快速拖动滑块时，前一轮预览会被 `OperationCanceledException` 中断，保证不堆积 FFmpeg 进程。

**预览图加载**：`PathToImageSourceConverter` 以 `BitmapCacheOption.OnLoad` + `IgnoreImageCache` + `DecodePixelWidth=620` 加载并 `Freeze()`，避免文件被占用、避免重复解码大图。

**体积对比文案**：`CompareResultText` = 「约 128.4KB（节省 62.3%）」，节省比例为 `(1 - 预览体积 / 原体积) × 100`，负数会被钳制为 0。

**最长边缩放**：`ScalePercentFor(item)` 用预览探测到的原图宽高计算：若最长边超过上限，则返回 `round(max * 100 / longest)`，否则 100%。

**压缩执行**：逐张顺序执行，每张独立解析输出路径（含冲突策略），成功即写入历史（`DurationSeconds = 0`），结束后汇总「压缩完成：成功 x，失败 y，跳过 z，取消 w」并附带打开位置动作。

## 6. 转换内核

### 6.1 FFmpeg 定位（`Core/FfmpegLocator.cs`）

查找顺序（逐个 `File.Exists` 命中即返回）：

```text
1. 设置中指定的目录（FfmpegDirectory，支持直接填 .exe 路径）
2. <EXE目录>\ffmpeg\bin\<exe>
3. <EXE目录>\ffmpeg\<exe>
4. <EXE目录>\tools\ffmpeg\bin\<exe>
5. <EXE目录>\<exe>
6. 系统 PATH 中各目录
```

`IsAvailable(out message)` 要求 **ffmpeg 与 ffprobe 同时存在**，缺失时返回可读的中文提示（"未找到 ffmpeg.exe，请在设置中指定 FFmpeg 目录……"）。`GetFfmpegVersion()` 通过 `ffmpeg -version` 正则提取 `ffmpeg version\s+(\S+)`，超时 5s，失败返回「读取失败」。

### 6.2 音频编码参数（`Core/FfmpegRunner.cs`）

参数由 `BuildArguments` 统一拼接，**页面不允许接触参数**：

```text
公共前缀：-hide_banner -nostdin -y
输入：    -i "<input>"
流映射：  视频输入 → -map 0:a:0? -vn -sn -dn     （提取第一条音轨，丢弃视频/字幕/数据）
          音频输入 → -map 0:a:0?
编码器：
  MP3  → -c:a libmp3lame -b:a 320k -write_xing 1 -id3v2_version 3
  WAV  → -c:a pcm_s16le
  FLAC → -c:a flac -compression_level 5
公共后缀：-map_metadata 0 -progress pipe:1 -nostats "<output>"
```

固定参数是刻意的产品决策：**避免用户手输 FFmpeg 参数导致转换失败**。

### 6.3 图片编码参数（`Core/ImageFfmpegRunner.cs`）

```text
公共前缀：-hide_banner -nostdin -y -i "<input>" -frames:v 1 -an
缩放（仅当 0 < scalePercent != 100）：
  -vf scale=trunc(iw*<f>/2)*2:trunc(ih*<f>/2)*2    （f = scalePercent/100，等比且保持偶数边）
编码器：
  JPG  → -c:v mjpeg -q:v <q>，q = clamp(2, 31, 2 + round((100 - clamp(1,100,quality)) * 0.29))
  PNG  → -c:v png -compression_level 9
  WebP → -c:v libwebp -quality <clamp(1,100,q)> -compression_level 6
```

注意：画质 100 对应 JPG `-q:v 2`（质量最好），画质 1 对应 `-q:v 31`（压缩最强），滑块方向与 FFmpeg 的 q 值方向相反，换算由上式完成。

### 6.4 媒体探测（`Core/FfprobeRunner.cs`）

```text
ffprobe -v error -of default=noprint_wrappers=1
        -show_entries format=duration:format=size:format=format_name
        -show_entries stream=codec_type,width,height
        "<file>"
```

解析为 `MediaInfo`：`HasAudio`、`HasVideo`、`Width`、`Height`、`DurationSeconds`、`SizeBytes`、`FormatName`。超时 8s；若 stderr 非空且既无音频流也无视频流，抛出带精简错误信息的 `InvalidOperationException`。

### 6.5 进度解析（`FfmpegRunner.TryParseProgress`）

依赖 `-progress pipe:1` 输出的 `key=value` 行：

- `out_time_us=<微秒>` → 秒 = `us / 1e6`，百分比 = `clamp(0, 99, 秒数 / 总时长 × 100)`；**上限锁 99**，只有 FFmpeg 退出码为 0 才上报 100；
- `speed=<值>` → 速度文本（如 `2.31x`）；
- 读到 `progress=end` 立即跳出读取循环。

取消采用 `CancellationToken.Register(() => process.Kill())`，读完进度后 `WaitForExit(8000)`，超时再强杀。错误信息只保留 stderr 的最后 8 行并用 ` | ` 连接，避免把整段 FFmpeg 日志塞进弹窗。

### 6.6 任务队列（`Core/ConversionTaskManager.cs`）

**顺序执行**：一次只转换一个文件（`for` 循环串行 `await`），避免多进程争抢磁盘 IO 导致整体变慢。

单个任务的处理流程：

```text
1. 若整体已取消 → Cancelled（ErrorCode=CANCELLED）
2. OutputPathResolver.Resolve() → Skip 则直接 Skipped（ErrorCode=OUTPUT_EXISTS）
3. Directory.CreateDirectory(目标目录) → 失败则 Failed（OUTPUT_DIR_ERROR）
4. 上报 TaskRunning
5. maxAttempts = AutoRetry ? max(1, RetryLimit + 1) : 1
   循环 attempt = 1..maxAttempts：
     a. FfprobeRunner 探测；无音频流 → Failed（NO_AUDIO_STREAM）并跳出
     b. FfmpegRunner 转换；成功 → Completed（读取输出文件大小）并跳出
     c. 失败 → Failed（FFMPEG_EXIT_<attempt>），若还有重试机会则置 final=null 继续
     d. 取消 → Cancelled；其它异常 → Failed（RUNNER_ERROR）
6. 记录 Stopwatch 耗时 → 上报 TaskCompleted / TaskFailed / TaskCancelled / TaskSkipped
```

更新通过 `IProgress<ConversionTaskUpdate>` 上报。ViewModel 用 `Progress<T>` 包装，`Progress<T>` 会捕获创建时的 `SynchronizationContext`（UI 线程），因此**进度与状态更新天然回到 UI 线程**，无需额外 `Dispatcher.Invoke`。

### 6.7 输出路径与冲突策略

**目录解析（`Core/OutputLocation.cs`）**

| 模式 | 目录 | 备注 |
| --- | --- | --- |
| `ProgramFolder`（默认，值 0） | `<EXE目录>\转换输出` | 启动即创建；必须保持枚举值为 0，旧配置缺字段时才能落到默认值 |
| `SourceFolder` | `<源文件目录>\转换输出` | 每个源文件各自解析 |
| `Custom` | 用户指定固定目录 | 若盘符在本机不存在则回退到程序目录 |

**可写性探测**：`IsProgramFolderWritable()` 首次调用时真实写入并删除一个 `.write-test-<guid>.tmp` 探针文件，结果在进程内缓存。程序目录不可写（例如装在 `C:\Program Files`）时，默认模式自动回退到「源文件所在文件夹」，**保证转换不失败**。

**文件名解析（`Core/OutputPathResolver.cs`）**

```text
candidate = <输出目录>\<源文件主名>.<目标格式小写>

若 candidate 不存在                        → Create
若 candidate 与源文件路径相同（同名同目录）  → 强制改名 GetUniqueName()（绝不覆盖源文件）
否则按冲突策略：
  Overwrite → Create（覆盖）
  Skip      → Skip
  Rename    → GetUniqueName()：<主名> (1).<ext>、 (2)… 最多试到 9999
              仍冲突则用 <主名>_<6位guid>.<ext>
```

图片模块在 `ImageCompressionViewModel.ResolveOutput` 中实现了等价的策略（因为输出扩展名由用户选择的格式决定，且需要额外排除"改出的名字又撞上源文件"的情况）。

### 6.8 错误码表

| 错误码 | 含义 | 触发位置 |
| --- | --- | --- |
| `CANCELLED` | 用户取消 | 任务开始前已取消 / 转换中被取消 |
| `OUTPUT_EXISTS` | 输出文件已存在且策略为跳过 | `OutputPathResolver` |
| `OUTPUT_DIR_ERROR` | 输出目录不可用（创建失败） | `ConversionTaskManager` |
| `NO_AUDIO_STREAM` | 文件中没有可转换的音频流 | `FfprobeRunner` 探测结果 |
| `FFMPEG_EXIT_<n>` | FFmpeg 非零退出（n 为第几次尝试） | `FfmpegRunner` |
| `RUNNER_ERROR` | 调用过程抛出异常 | `ConversionTaskManager` |
| `UNKNOWN` | 重试逻辑异常兜底 | `ConversionTaskManager` |

### 7.3 JSON 序列化（`Data/JsonFile.cs`）

- 只用 .NET 自带 `DataContractJsonSerializer`，不引入 Newtonsoft；
- `Load<T>` 失败（文件不存在 / 损坏 / 反序列化异常）一律返回 `null`，由调用方回落到默认值；
- `Save<T>` 自动创建父目录，输出 UTF-8 **无 BOM**；
- `HistoryService` 内部用 `lock (_sync)` 保护列表，并且 `SaveCore()` 的异常被吞掉——**历史写入失败绝不能影响转换主流程**。

### 7.4 旧配置迁移

`SettingsService` 构造时做一次清理：

- 若输出模式不是 `Custom`，把残留的 `OutputDirectory` / `ImageOutputDirectory` 置空（避免"看着还是别的电脑的旧路径"）；
- 图片自定义目录为空时继承音频的自定义目录；
- 日志目录、临时目录为空时填默认值；`HistoryLimit <= 0` 时重置为 200；
- 只要发生了清理就立即落盘一次，保证 `settings.json` 本身也不再残留它机路径。

## 8. UI 设计规范

### 8.1 设计语言

风格基准：**浅色、低饱和、无渐变、圆角卡片、留白充足**（参照 FlClash / PCL2 / Codex Desktop 的视觉气质）。

核心原则：

- 一张卡片一个语义块，卡片间留 10px 垂直间距；

**中性色**

| 令牌 | 色值 | 用途 |

| 属性 | 值 |
| --- | --- |
| 尺寸 | 宽 400，高度自适应内容 |
| 容器 | `Surface` 底 + `BorderStronger` 描边 1.5px + 圆角 12 + 内边距 20 |
| 投影 | `DropShadowEffect{Blur=32, Depth=3, Opacity=0.22}` |
| 图标 | 28×28 圆角 14 色块 + 加粗字形：成功 `✓`（绿）、错误 `✕`（红）、警告 `!`（红）、信息 `i`（红） |

**键盘**：`Esc` 关闭并返回否定结果；确认按钮为 `IsDefault`，回车即确认。

## 9. 交互规范

### 9.1 通用交互约定

- 所有耗时操作（转换、压缩、探测、预览）**不阻塞 UI 线程**，均通过 `async/await` + `ConfigureAwait` 实现；
- `AsyncRelayCommand` 内部用 `_isExecuting` 防重入，执行前后调用 `CommandManager.InvalidateRequerySuggested()`；
- 所有命令的 `CanExecute` 通过 `CommandManager.RequerySuggested` 挂接，配合 `InvalidateRequerySuggested()` 实时刷新按钮可用性；
- 转换 / 压缩运行中禁止移除文件与清空列表（`CanRemove` / `CanClearAll` 返回 `false`）；
- 破坏性操作（清空历史、删除单条历史、恢复默认设置）必须先弹确认框。

### 9.2 拖拽上传

上传区（`DropArea`）在页面根节点上启用 `AllowDrop="True"` + `PreviewDragOver` + `Drop`：

- **音频页**：`OnDragOver` 判断载荷含 `DataFormats.FileDrop` 时把 `DropArea` 底色改为 `Brush.AccentSoft`、描边改为 `Brush.Accent`（高亮反馈）；`OnDrop` 恢复为 `#FAFAFA` 底 + `#D4DDE5` 描边，并把文件数组交给 `ViewModel.AddPaths`；非文件拖入时 `Effects = None`（禁止落下）。上传区内部是 64×64 `AccentSoft` 圆形 + 30×30 上传箭头，主文案 15px SemiBold，下方附一个「点击添加文件」的伪按钮边框。
- **图片页**：`OnDragOver` 只设置 `Effects = Copy/None`，不做变色；上传区随列表状态切换两套内容——空列表显示 68×68 圆形 + 「将图片拖到这里，或点击此区域添加」，非空时切换为 38×38 小圆形 + 「可继续添加图片」（由 `IsEmpty` / `InverseBool` 控制可见性）。
- **整块可点击**：`DropArea` 内部叠一个 `Style="{StaticResource DropOverlayButton}"` 的透明全尺寸按钮（`AutomationProperties.Name` 分别为"添加文件"/"添加图片"），`Command="{Binding AddFilesCommand}"`，因此点击区域任意位置都等价于点「点击添加文件」。
- **校验与去重**：`AddPaths` 逐个校验扩展名白名单 + `File.Exists` + `FilePath` 去重，不合格的静默跳过，不打断其余文件入列。

### 9.3 快捷键与键盘

| 按键 | 行为 |
| --- | --- |
| `Esc` | 关闭当前弹窗（返回否定结果） |
| `Enter` | 触发弹窗默认按钮（确认 / 确定） |
| 双击标题栏 | 最大化 / 还原 |
| 按住标题栏拖动 | 移动窗口（`DragMove()`） |

### 9.4 设置页滚动联动

设置页左侧是 `TreeView`（`SectionTree`，两级：分组 → 小节），右侧是 `ScrollViewer`（`SettingsScroll`），双向联动：

- **滚动 → 导航**：`OnSettingsScrollChanged` 以 `VerticalOffset + ViewportHeight * 0.35` 为判定线，遍历八个 `Section*` 元素（音频默认 / 图片默认 / 音频输出 / 图片输出 / 转换 / 文件冲突 / 任务 / 存储），取最后一个顶部越过判定线的元素作为当前小节，写回 `SelectedSection` 并同步树选中项。`_updatingFromScroll` 标志防止双向触发死循环。
- **导航 → 滚动**：`OnSectionTreeSelectionChanged` 取目标元素相对内容面板的 Y 偏移，用 `DoubleAnimation(from → top-8, 260ms, QuadraticEase/Out)` 动画化附加属性 `AnimatedVerticalOffset`，在回调里调用 `ScrollToVerticalOffset` 实现平滑滚动。

### 9.5 页面内布局动画

| 动画 | 触发 | 参数 |
| --- | --- | --- |
| 图片页上传区收缩 | 列表由空变为非空 | 顶行高度从当前实际像素（至少 160）动画到 118px，280ms（`GridLengthAnimation`）；清空列表时直接回到 `1*`，不做动画 |
| 图片页预览切换 | 点上/下一张 | `PreviewHost.Opacity` 由 0 → 1，120ms，`QuadraticEase/Out` |
| 历史页刷新 | 页面变为可见（`IsVisibleChanged`） | 重新从 `HistoryService` 载入记录并更新列头排序箭头 |

## 10. Windows 7 兼容性设计

### 10.1 兼容性清单

- 目标系统：Windows 7 SP1 **64 位**（主程序为 x64，32 位系统不支持）；
- 目标框架 `net48`：Win7 SP1 可安装的最高主流 .NET Framework 版本；
- `app.manifest` 保留 `supportedOS` 的 Win7 / 8 / 8.1 / 10 / 11 四个 GUID 声明，并保持 `dpiAware=true`；

- 图标与导航图形全部使用纯 `Path`/`Geometry` 矢量，不使用字体图标；
- 动画只使用 WPF 原生 `DoubleAnimation` / 自定义 `GridLengthAnimation`，不依赖合成引擎高级特性。

### 11.3 代码签名（`scripts/sign-release.ps1`）

```powershell
# 正式签名（需要 .pfx 证书 + Windows SDK 的 signtool.exe）
powershell -ExecutionPolicy Bypass -File scripts\sign-release.ps1 `
  -CertPath "D:\certs\skyfusion.pfx" -CertPassword "密码" `
  -ExePath "artifacts\SkyFusion\SkyFusion.exe"
```

## 12. 安全与隐私

### 12.1 行为边界（必须始终满足）

- **无网络行为**：不下载、不上传、不联网校验、不自更新、无遥测；
- **无系统侵入**：不注入进程、不装驱动、不装服务、不写注册表、不修改系统设置；
- **不越权**：`asInvoker` 运行，不请求管理员权限（安装包除外，安装本身需要写 `Program Files`）；
- **不丢用户数据**：输出路径与源文件同名时强制改名，**绝不覆盖源文件**；
- **失败可恢复**：日志/历史写入失败静默忽略，不影响转换主流程。

### 12.2 数据落点

程序只在 `%APPDATA%\AudioConverter\`（设置、历史、日志）、`%TEMP%\AudioConverter\`（图片预览临时文件）、程序目录或用户指定目录（转换输出）三处写文件。

### 12.3 杀软误报与应对

Windows Defender 曾把未签名的 `SkyFusion.exe` 报为 `Trojan:Win32/Bearfoos.A!ml`。`!ml` 结尾表示该结果来自**机器学习启发式**而非特征库命中——对新编译、未签名、且会启动外部进程的桌面程序，这类误报比较常见。

**根治方案（推荐）**：

1. 使用正规代码签名证书（OV/EV Code Signing）对每次发布签名；
2. 发布到 GitHub Releases，通过长期信誉降低误报；
3. 被误报后向 Microsoft 提交误报申诉：<https://www.microsoft.com/en-us/wdsi/filesubmission>，选择「Microsoft Defender Antivirus 误报」，说明这是离线格式转换工具、调用本机 FFmpeg。

**临时方案（仅开发机）**：

```powershell
Add-MpPreference -ExclusionPath "D:\文档\ChatGPT\天融格式转换软件"
```

不要把「让最终用户加白名单」当作正式方案。

### 16.2 FFmpeg 参数速查

```powershell
# MP3（320 kbps CBR，写入 Xing 头，ID3v2.3）
-c:a libmp3lame -b:a 320k -write_xing 1 -id3v2_version 3

# WAV（16-bit PCM）
-c:a pcm_s16le

# FLAC（压缩等级 5）
-c:a flac -compression_level 5

# JPG（q:v 2 最好 … 31 最省）
-c:v mjpeg -q:v <2..31>

# PNG（无损，最大压缩）
-c:v png -compression_level 9

# WebP（有损，quality 1..100，压缩等级 6）
-c:v libwebp -quality <1..100> -compression_level 6

# 等比缩放且保持偶数边（f = 百分比 / 100）
-vf scale=trunc(iw*<f>/2)*2:trunc(ih*<f>/2)*2
```
