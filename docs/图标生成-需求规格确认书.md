## 一、项目目标与成功标准

| 项 | 内容 | 来源 |
| --- | --- | --- |
| 目标 | 为天融 SkyFusion 增加 ICO 图标生成能力，填补文档中长期标注的「`.ico` 转换未实现」 | 用户原话："添加一个转换ico图标的功能" |
| 解决什么 | 用户需要把自有图片（Logo / 截图）变成 Windows 可用的 `.ico`，现有工具链完全做不到 | 用户选定 4 类用途：应用程序与快捷方式图标 / 网站 favicon / 从现有图片抠一个图标 / 批量转换素材库 |
| 成功标准 | 100 张 4000×3000 源图的批量转换 ≤ **120 秒**完成，内存峰值 ≤ **400 MB** | 用户选定指标 |
| 明确不做 | ICO → 图片（本期）、PNG 同时导出、SVG 输入、多图合并、自定义画质参数 | 用户明确选择 |

## 二、用户与使用场景

- **使用者**：需要图标的离线单机用户（内网 / 无外网终端），非专业设计人员。
- **环境**：Windows 10 1903+ / Windows 11 x64。
  **产品基线正式从 Win7 SP1 上移** —— 用户原话："产品级决定，正式放弃 Win7"。
- **典型流程（批量）**：拖入图片 → 列表显示待生成 → 点「开始生成」→ 顺序处理 →
  每行显示「已生成 16/32/48/256」与文件大小 → 可打开输出位置。
- **精调流程（单张）**：双击某一行 → 裁剪弹窗 → 拖框选区域 → 确定 → 该图按新裁剪区域生成。

### 3.3 明确不做（本期排除）

| 排除项 | 理由 |
| --- | --- |
| ICO → 图片 | 用户："本期不做，但架构预留"（Core 接口 / 模型 / 文件过滤器预留 `.ico` 作为输入） |

| SVG 矢量输入 | 需外部库，破坏离线与体积约束 |
| 多张图合并成一个 ICO | 用户未选 |
| 画质滑块 | 用户："ICO 只做等比缩放到目标尺寸" |
| 主动刷新 Windows 图标缓存 | 用户授权「按你推荐的来」= 只在文档写一句提示 |
| 并发 / 多进程加速 | 性能余量 11 倍，无需并发；并发会抬高内存，与「低配机也能跑」冲突 |
| 「以程序图标为源图」快捷入口 | 用户：「不需要，保持简洁」 |

## 五、数据设计

| 项 | 设计 |
| --- | --- |
| 输入 | 文件路径（**不复制源文件**） |
| 裁剪区域 | 内存态，随列表项存在，`{X, Y, W, H}`；未裁剪 = null（走默认居中裁剪）。**不持久化**，程序重启后丢失（见假设 A2） |
| 输出 | 单个 `.ico`，命名 = 源文件名，例如 `logo.png` → `logo.ico` |
| 历史记录 | 复用 `Models/HistoryEntry`，一次转换记一条，字段沿用现有结构 |
| 设置 | 复用 `%APPDATA%\AudioConverter\settings.json`，**不新增字段** |
| 中间数据 | **零中间文件**：4 个尺寸的 PNG 走 ffmpeg stdout 管道直接进内存 |
| 生命周期 | 转换结束即释放；不落盘、不缓存 |

## 六、技术方案

| 项 | 决定 | 依据 |
| --- | --- | --- |
| 目标框架 | **维持 `net48`** | Win10 1903+ / Win11 自带 .NET Framework 4.8，用户免装运行时，风险最低 |
| 依赖 | **本期不引入任何第三方库** | ffmpeg 本身即开源方案；ICO 写入标准很窄，自写容器更可控。用户允许引库但设了硬条件（完全离线 / 免费 / 无需认证授权），**不引入即零风险** |
| 缩放 | 纯 ffmpeg，`scale=...:flags=lanczos` | 用户选定方案 A |
| 进程模型 | **1 张图 = 1 个 ffmpeg 进程**；4 个 `png_pipe` 输出写 stdout，C# 捕获后拼装 ICONDIR | 已实测验证 |
| ICO 容器 | 自写：6 字节 ICONDIR + 每尺寸 16 字节目录项 + PNG 数据，各字段按规范填写 | ffmpeg 原生 ICO 写入器将 `declaredBpp` 恒填 1，非标准；自写可控 |
| 小尺寸清晰度 | 源图短边 < 目标尺寸 → 跳过该尺寸，不放大 | 用户选定 |
| 文件对话框 | 过滤 `*.png;*.jpg;*.jpeg;*.webp;*.bmp` | 用户选定 |
| 分层 | View → ViewModel → Services → Core，新增 `Core/IcoWriter.cs`，无 UI 依赖 | 项目既有分层约束 |
| 新增文件 | `Modules/IconGeneration/`（View / ViewModel / ItemViewModel）、`Core/IcoWriter.cs`、`Core/IconRunner.cs`；`Shell/AppPage.cs`、`Shell/ShellViewModel.cs`、`Shell/ShellDataTemplates.xaml` 各改一处 | 见 `docs/技术文档.md` 15.2「新增页面标准动作」 |

### 6.1 已实测验证的关键技术点

| 验证项 | 结果 |
| --- | --- |
| ffmpeg 写 `.ico` | ⚠️ 仅 `-c:v png` 路径可行；默认编码器与 `-c:v bmp` / `-c:v mjpeg` 报 `Could not write header (incorrect codec parameters ?)` |
| 一次调用出多尺寸 | ✅ `split` + `scale` + 多 `-map`，产出 `count=3` 的合法 ICO |
| 管道方案 | ✅ **exit=0，stdout 16282 字节，4 个完整 PNG，尾部 IEND 正确** |
| ICO 结构 | ✅ `reserved=0, type=1`，目录项 16 字节，偏移正确，条目内为 PNG（magic `89 50 4E 47`） |
| 尺寸准确性 | ✅ 实测 16×16 / 32×32 / 256×256 三项字节数 678 / 1390 / 8707 |
| 透明度保留 | ✅ 解码回读 `pix_fmt=rgba` |
| 体积差异 | ⚠️ 256×256 条目：PNG 版 588 B、BMP 版 205 KB（350 倍）→ **必须强制 PNG** |
| ffmpeg 原生 ICO 的 `declaredBpp` | ⚠️ 恒为 1，非标准（PNG 条目下该字段无实际作用）→ 自写容器规避 |

## 七、非功能要求

| 项 | 指标 | 备注 |
| --- | --- | --- |
| 性能 | 100 张 4000×3000 ≤ **120 秒** | **实测 0.104 秒/张（含 ffmpeg 启动开销约 0.084 秒）→ 100 张约 10.4 秒，余量约 11 倍** |
| 内存 | 峰值 ≤ **400 MB** | 不缓存整图；中间数据仅 4 个小 PNG |
| 离线 | **零网络调用** | 不下载、不联网校验、不遥测 |
| 兼容 | Windows 10 1903+ / Windows 11 x64 | **Win7 支持正式终止** |
| 发布包体积 | 不新增任何运行时文件 | 不引依赖 = 体积零增长 |
| 资源 | 低配机可用：严格串行、单进程、用完即释放 | 用户要求「低配机也能跑」 |

## 八、交付形态与验收标准

**交付**：源码（仓库）+ Release 资产（便携 zip + 安装包），沿用现有发布流程。

| # | 验收标准（可检验） | 验证方式 |
| --- | --- | --- |
| A1 | Release 构建 **0 警告 0 错误** | `dotnet build AudioConverter.sln -c Release` |
| A2 | 生成的 `.ico` 结构合法：`reserved=0, type=1, count=4` | 解析前 6 字节 |
| A3 | 四个条目尺寸正确为 16 / 32 / 48 / 256 | 解析 4 个 16 字节目录项 |
| A4 | 每个条目内部为 PNG（magic `89 50 4E 47`） | 按偏移读 magic |
| A5 | 透明保留：解码回读 `pix_fmt=rgba` | `ffprobe` 回读 |
| A6 | 源图短边 < 256 时不产生放大条目 | 用 64×64 源图，检查 `count=3` |
| A7 | 非正方形源图输出为正方形图标 | 用 4000×3000 源图，解码回读为正方形 |
| A8 | 100 张批量 ≤ 120 秒，内存峰值 ≤ 400 MB | 实测计时 + 进程内存采样 |
| A9 | 历史记录写入成功且可打开输出位置 | 检查 `history.json` + 点击验证 |
| A10 | 同名 `.ico` 存在时按冲突策略处理，**绝不覆盖源文件** | 同一张图重复转换三次 |
| A11 | **Windows 中实际显示正确**（资源管理器各视图 / 任务栏 / 快捷方式） | **用户人工确认**（无头环境无法看到渲染结果） |
| A12 | 裁剪弹窗生效：同一源图两种裁剪区域产出不同图标 | 对比两次输出的解码像素 |

**验收方式授权**：用户原话"按你推荐的来" = 结构级自动验证（A1–A10、A12）+ 人工确认（A11）；
不含像素级逐点回归比对。
